# El Grande Mobile — Android

Android app shell for the existing All by Devoll Python desk, with a phone-private SQLite database. The desktop installation remains unchanged.

## Development build

Run GitHub Actions **El Grande Android APK** (or from the `android/` directory run `gradle :app:assembleDebug` with Java 17, Android SDK and Python 3.12 installed).

The workflow provides an APK artifact under its run's **Artifacts** section. Download it, then copy `app-debug.apk` to the company website and offer it as a direct download. Android users may need to permit installation from their browser. Keep the same application ID and signing key to support updates preserving phone-local data.

This uses Chaquopy to package Python, existing dashboard modules, and SQLite. It starts the desk on phone-only loopback, authenticates requests with a random in-memory session cookie, and displays it using Android WebView. Invoice PDFs are generated by Android's native PDF API and shared via the system share sheet. The phone does not rely on the desktop or on a hosted backend to manage local shop data.

## Important behavior

* **Local records:** Each Android installation has its own database in the app's private storage. It does not synchronize records with another phone or desktop. Removing app data or uninstalling it deletes local records: export them before doing so.
* **External integrations:** Gmail imports, Plaid, catalog feeds, and model-based estimate assistance depend on their own network services/configuration. The native WebView bridge and Android background lifecycle need device testing for each integration. No office computer is required for core job and ledger records.
* **APK signing:** Debug artifacts are for installation testing, not a production release/update channel. For production website distribution, configure a protected release signing key in GitHub secrets and publish a release-signed APK. Never commit the signing key or passwords.
* **Android testing:** Test job creation, changes, appointment saving, finalization, payment recording, invoice PDF sharing, SQLite persistence after force-close/reboot, and device rotation on a real Android phone before offering it to operators.

Source: `integrations/all_by_devoll/` is shared with the desktop version, while mobile-only startup lives in `android/app/src/main/python/mobile_server.py`.
